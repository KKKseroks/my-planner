МОЙ ПЛАНЕР — PWA + FIREBASE
===========================

1. СОЗДАЙТЕ ПРОЕКТ FIREBASE
- Откройте https://console.firebase.google.com/
- Add project / Создать проект. Google Analytics можно отключить.
- В настройках проекта нажмите значок </> (Web app / Веб-приложение).
- Зарегистрируйте веб-приложение, скопируйте объект firebaseConfig.
- Откройте файл firebase-config.js и замените значения PASTE_... на реальные значения.
  ВНИМАНИЕ: сохраняйте имена полей без изменений. Не вставляйте сюда приватные ключи сервисных аккаунтов.

2. НАСТРОЙТЕ ВХОД
- Firebase Console → Build → Authentication → Get started → Sign-in method.
- Включите Email/Password (Электронная почта/Пароль).
- Authentication → Settings → Authorized domains: добавьте username.github.io,
  где username — ваш логин GitHub. Если используете собственный домен, добавьте и его.

3. СОЗДАЙТЕ БАЗУ
- Build → Firestore Database → Create database.
- Выберите регион и создайте базу. Можно начать с Production mode.
- Откройте вкладку Rules, замените правила содержимым файла firestore.rules.
- Нажмите Publish. Эти правила позволяют каждому пользователю читать только свои данные.

4. ОПУБЛИКУЙТЕ САЙТ
- Зарегистрируйтесь на https://github.com/.
- Создайте PUBLIC-репозиторий, например my-planner.
- Загрузите ВЕСЬ набор файлов из этой папки, сохраняя папку icons.
- В репозитории Settings → Pages → Build and deployment:
  Source = Deploy from a branch, Branch = main, Folder = /(root), Save.
- Дождитесь появления ссылки https://USERNAME.github.io/my-planner/.
- Откройте ссылку на компьютере, создайте аккаунт и проверьте добавление задачи.
- Откройте эту же ссылку на телефоне и войдите с ТОЙ ЖЕ почтой и паролем.

5. УСТАНОВКА НА ТЕЛЕФОН
Android: откройте ссылку в Chrome → меню ⋮ → «Установить приложение»
или «Добавить на главный экран».
iPhone: откройте ссылку в Safari → Поделиться → «На экран Домой».
Название пунктов может немного отличаться по версии ОС.

6. КАК РАБОТАЮТ СТАРЫЕ ЗАПИСИ
- При первом входе существующие локальные записи в браузере загружаются в пустой аккаунт.
- Если в аккаунте уже есть облачные записи, они имеют приоритет над локальными.
- Поэтому сначала войдите на том компьютере/в том браузере, где хранятся ваши старые задачи.
- Перед переносом сделайте резервную копию браузерных данных. Не очищайте данные сайта.
- Не создавайте несколько аккаунтов для одного планера.

7. ОГРАНИЧЕНИЯ ЭТОЙ ВЕРСИИ
- Синхронизация выполняется по разделам данных. Если редактировать один раздел
  одновременно на двух устройствах, последнее сохранение может перезаписать изменения.
- При поступлении изменений с другого устройства страница может перезагрузиться,
  чтобы обновить данные в интерфейсе. Во время заполнения формы обновление откладывается.
- Firebase требует интернет для первого входа и настройки. Работа офлайн зависит
  от кеша браузера; офлайн-изменения могут синхронизироваться позже, когда сеть появится.
- Функция «Выйти» не очищает локальный кеш. На общем компьютере используйте отдельный
  профиль браузера и не храните в планере чувствительные данные.
- При удалении браузерного кеша несинхронизированные записи могут исчезнуть.
- Бесплатные лимиты Firebase могут измениться, следите за использованием в консоли.

8. ЕСЛИ НЕ РАБОТАЕТ
- «Сначала заполните firebase-config.js»: не заменены значения PASTE_...
- «permission-denied»: проверьте опубликованные Firestore Rules.
- «auth/operation-not-allowed»: включите Email/Password.
- Если сайт показывает старую версию, обновите страницу и проверьте кеш приложения.
- Не открывайте index.html через file:// для настройки Firebase: нужен http(s).

СОСТАВ ПРОЕКТА
index.html — страницы и окно входа
style.css — исходное оформление + окно входа
script.js — исходная логика планера
sync.js — авторизация и облачная синхронизация
firebase-config.js — настройки вашего Firebase-проекта
firestore.rules — правила защиты облачной базы
manifest.webmanifest — настройки установки PWA
sw.js — кеширование файлов приложения
icons/ — иконки приложения
